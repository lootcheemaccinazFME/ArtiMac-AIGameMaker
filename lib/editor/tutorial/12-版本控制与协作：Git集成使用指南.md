## Git集成概述

ArtiMeow内置了Git版本控制系统，让你可以：
- **跟踪变更**: 记录项目的每次修改
- **版本回滚**: 恢复到任意历史版本
- **分支开发**: 并行开发不同的故事线
- **团队协作**: 多人共同开发同一项目

## Git基础概念

### 版本控制的重要性
- 防止意外丢失工作
- 跟踪项目发展历史
- 支持实验性修改
- 便于团队协作

### Git术语解释
- **仓库(Repository)**: 项目的存储位置
- **提交(Commit)**: 保存一次修改记录
- **分支(Branch)**: 独立的开发线
- **合并(Merge)**: 将分支的修改合并到主线

## 初始化Git仓库

### 1. 创建本地仓库
1. 打开项目设置界面
2. 找到"版本控制"选项卡
3. 点击"初始化Git仓库"按钮
4. 系统会在项目目录创建Git仓库

### 2. 配置用户信息
```
设置姓名: git config user.name "你的名字"
设置邮箱: git config user.email "your@email.com"
```

### 3. 首次提交
1. 添加所有项目文件到暂存区
2. 输入提交描述："初始项目提交"
3. 点击"提交"按钮创建第一个版本

## 日常Git操作

### 1. 查看项目状态
在Git面板中可以看到：
- 已修改的文件列表
- 新增的文件
- 已删除的文件
- 当前分支信息

### 2. 提交更改
**标准提交流程**
1. 查看修改的文件列表
2. 选择要提交的文件
3. 写入有意义的提交信息
4. 点击"提交"保存更改

**提交信息规范**
```
好的提交信息示例：
- "添加第三章：图书馆相遇"
- "修复选择分支跳转错误"
- "更新艾莉丝角色立绘"
- "优化背景音乐播放逻辑"

避免的提交信息：
- "修改"
- "更新文件"
- "bug fix"
```

### 3. 查看提交历史
1. 点击"历史记录"选项卡
2. 浏览所有提交记录
3. 查看每次提交的具体变更
4. 比较不同版本的差异

## 分支管理

### 1. 创建新分支
**使用场景**
- 开发新的故事线
- 实验性功能
- 修复bug
- 团队成员独立工作

**创建步骤**
1. 右击当前分支
2. 选择"创建新分支"
3. 输入分支名称（如"新结局分支"）
4. 选择基于哪个提交创建

### 2. 切换分支
1. 在分支列表中选择目标分支
2. 点击"切换"按钮
3. 工作区文件会自动更新到该分支状态

### 3. 合并分支
当分支开发完成后：
1. 切换到主分支
2. 选择要合并的分支
3. 点击"合并分支"
4. 解决可能的冲突

## 远程仓库协作

### 1. 连接远程仓库
**GitHub集成**
1. 在GitHub创建新的仓库
2. 复制仓库URL
3. 在ArtiMeow中添加远程地址
4. 配置身份验证

**其他Git服务**
- GitLab
- Bitbucket  
- 私有Git服务器

### 2. 推送和拉取
**推送本地更改**
1. 确保本地更改已提交
2. 点击"推送"按钮
3. 选择要推送的分支
4. 输入身份验证信息

**拉取远程更改**
1. 点击"拉取"按钮
2. 系统会下载远程更改
3. 自动合并到本地分支
4. 解决可能的合并冲突

## 冲突解决

### 1. 理解合并冲突
当同一个文件被不同的人修改时，会产生冲突：
```
<<<<<<< HEAD
原始内容
=======
修改后的内容
>>>>>>> 分支名
```

### 2. 解决冲突步骤
1. 打开冲突文件
2. 手动选择要保留的内容
3. 删除冲突标记符号
4. 保存文件并提交

### 3. 预防冲突的方法
- 经常拉取远程更改
- 协调修改不同的文件
- 使用分支隔离功能开发
- 及时沟通修改计划

## 常见问题解答

**Q: 误删了重要文件怎么恢复？**
A: 使用Git历史记录恢复到删除前的版本。

**Q: 如何撤销最近的提交？**
A: 使用"重置"功能回到上一个提交状态。

**Q: 合并冲突太复杂怎么办？**
A: 可以放弃合并，重新整理后再次尝试。

**Q: 团队成员看不到我的更改？**
A: 检查是否已推送到远程仓库。

**Q: Git仓库太大影响性能？**
A: 清理历史记录，使用Git LFS管理大文件。
